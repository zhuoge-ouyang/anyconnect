# Windows 与 Android 联系作者二维码设计

## 目标

在不改变 VPN 登录、连接、分流和账号保存逻辑的前提下，统一优化 Windows 桌面端与 Android 客户端的“联系作者”体验：

- 登录状态下，在“联系作者”文字下方常驻显示微信二维码。
- 主界面不常驻显示二维码，只在右下角显示“联系作者”按钮；点击后弹出较大的二维码窗口。
- 两端使用同一张微信二维码源图，视觉文案与交互保持一致。

## 资源处理

以用户提供的 `C:\Users\MSI\Desktop\20260717-022449.jpg` 为唯一源图，裁出中央二维码主体，去掉头像、地区和大面积空白，生成适合界面缩放的方形 PNG。二维码模块不得重绘或生成，避免破坏可扫描性。

生成后的二维码分别进入现有资源管线：

- Windows：保存到 `internal/ui/assets`，构建与安装包脚本复制到运行目录的 `ui-assets`。
- Android：保存到 `android/app/src/main/res/drawable-nodpi`，由 APK 资源系统打包。

资源缺失时构建或打包检查直接失败，不增加运行时 fallback。

## Windows 桌面端

### 登录窗口

在现有登录卡片下方增加独立的“联系作者”区域。区域包含居中的标题、简短扫码说明和常驻二维码。登录窗口与内部容器按内容增高，保留固定窗口、DPI 缩放和现有账号输入交互；二维码按固定最大边长等比显示，不拉伸。

### 管理台

将当前位于“常用操作”按钮矩阵中的“联系作者”入口移到窗口右下角操作区；已有的“充值说明”等入口继续保留。点击后由当前 WinForms 窗口直接打开模态联系窗口，窗口包含标题、微信号、较大二维码和关闭按钮。该动作不再依赖管理台命令文件往返，因此二维码弹窗始终属于当前管理台窗口。

其他操作按钮重新排列以填补原按钮位置，但不改变其动作、文案或业务逻辑。托盘菜单的既有“联系作者”行为不在本次范围内。

## Android 客户端

Android 当前使用同一个 Activity 在未连接与已连接状态之间切换，因此联系区域也随状态切换：

- 未连接/登录状态：在登录表单后的“联系作者”标题下常驻显示二维码卡片，保留页面滚动能力，避免小屏设备内容被裁切。
- 已连接主界面：隐藏登录态常驻二维码，在根布局右下角显示“联系作者”按钮；按钮与系统安全区、页面内容保留间距，不覆盖主要操作。
- 点击主界面按钮：复用现有联系弹窗结构，加入较大的二维码、微信号和关闭操作；保留复制微信号能力。

二维码使用 `CENTER_INSIDE` 等比缩放，宽度受屏幕可用区域限制，高度跟随宽度，避免拉伸或与弹窗边缘重叠。

## 状态与数据流

二维码是只读静态资源，不经过网络加载，不写入配置或日志。

- Windows 登录窗口启动时从可执行文件旁的 `ui-assets` 读取图片。
- Windows 管理台启动时记录同一资源路径，按钮点击时创建并显示模态窗口。
- Android 创建页面时从 `drawable-nodpi` 加载资源；连接状态刷新只切换登录二维码区和右下角按钮的可见性。

## 错误处理

- Windows 构建和安装包阶段校验二维码文件存在，避免发布缺图版本。
- Windows 运行时若图片读取失败，联系区域显示明确的“二维码加载失败”提示，不用其他图片替代。
- Android 资源由编译器校验；资源缺失会使构建失败。
- 弹窗关闭不改变 VPN 状态、账号输入或连接流程。

## 测试与验收

- 先增加失败测试，确认 Windows 登录脚本包含联系标题、二维码资源路径与常驻图片控件。
- 先增加失败测试，确认 Windows 管理台右下角联系按钮和模态二维码窗口存在，原按钮矩阵不再包含联系按钮。
- 更新打包测试或脚本断言，确认 Windows payload 包含二维码 PNG。
- 增加 Android JVM 测试可验证的页面状态决策：未连接显示常驻二维码，已连接显示右下角按钮。
- 构建 Android APK，确认二维码资源被打包。
- 运行相关 Go 测试、全量 `go test ./...`、Windows 可执行文件构建和 Android 单元测试/assemble。
- 人工检查 Windows 登录页、Windows 管理台、Android 登录态和 Android 已连接态；确认二维码可被微信扫描、弹窗无裁切、按钮不遮挡主要内容。
