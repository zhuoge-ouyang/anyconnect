# 桌面端联系作者分页与管理台布局修订

## 目标

在不改变 VPN、线路、分流、账号和充值业务逻辑的前提下，修正桌面管理台的三个界面问题：

- 顶部左侧展示真实微信二维码缩略图，不再展示应用图标。
- “联系作者”改为同一窗口内的两页内容，第一页展示作者信息，第二页展示二维码。
- 底部“充值说明”和“联系作者”按钮在系统 DPI、标题栏和窗口边框占用空间后仍完整显示，不被压缩或裁切。

## 视觉方向

继续使用现有自然植物背景、暖白纸张卡片、墨绿色文字和青绿色主按钮，保持管理台已经形成的自然、克制风格。联系窗口参考用户提供的紧凑信息卡结构，但沿用现有管理台色彩和圆角按钮，不复制参考图的灰色工具窗口外观。

## 管理台顶部

- 顶部卡片左侧继续保留方形视觉位，改为读取 `ui-assets/wechat-contact-qr.png`。
- 二维码置于白色内衬中等比缩放，四周保留扫描静区，不裁剪、不拉伸。
- 二维码控件读取失败时显示明确的“二维码加载失败”文字，不用应用图标或其他图片替代。
- 标题区域适当加宽，完整显示“AnyConnect 分流管理台”，状态胶囊位置保持不变且不与标题重叠。

## 联系作者窗口

窗口使用固定客户区尺寸和同一个模态窗口原地翻页，不再打开第二个子窗口。

### 第一页：联系信息

从上到下展示：

- 标题：`联系作者`
- 说明：`有问题、建议或需要定制，可以联系作者。`
- 作者：`卓哥`
- 微信号：`ai_creater99`
- 补充说明：`需要安卓客户端请联系作者。`

底部操作：

- `复制微信号`：复制 `ai_creater99`，继续使用现有复制成功提示。
- `查看微信二维码`：在当前窗口切换到第二页。
- `关闭`：关闭联系窗口。

### 第二页：微信二维码

- 标题：`微信二维码`
- 提示：`微信扫码添加作者`
- 中央显示完整二维码，使用 `Zoom` 等比缩放并保留边距。
- 底部提供 `返回` 和 `关闭`。
- `返回`切换到第一页，`关闭`结束模态窗口。

两页使用两个容器面板控制可见性；窗口打开时固定从第一页开始。关闭窗口时释放二维码图片资源，避免文件被长期锁定。

## 管理台底部布局

- 主窗体改用明确的客户区尺寸，不再用包含标题栏和边框的外部 `Size` 计算内部坐标。
- 在两张主要内容卡片下方建立独立底部操作栏。
- `充值说明`和`联系作者`右对齐排列，并锚定到底部和右侧。
- 底部操作栏与内容卡片、窗口边缘保留稳定间距；窗口处于允许的最小尺寸时，按钮仍保持完整高度和文字。
- 不改变按钮动作，也不调整常用操作、诊断卡片和白名单输入的业务行为。

## 状态与错误处理

- 联系窗口分页只改变控件可见性，不写配置、不发送管理台命令。
- 二维码继续从本地静态资源加载，不经过网络。
- 资源缺失或加载失败时，第一页仍可复制微信号，第二页显示错误提示；不增加替代图片策略。

## 测试与验收

- 先增加失败测试，确认顶部图片读取 `wechat-contact-qr.png`，且不再把应用图标转为顶部位图。
- 先增加失败测试，确认联系窗口包含两个分页面板、指定文案及第一页到第二页和返回的事件。
- 先增加失败测试，确认主窗体使用 `ClientSize`，底部操作栏和两个按钮具备底部/右侧锚定。
- 运行 `go test ./internal/ui -count=1` 和 `go test ./... -count=1`。
- 重打桌面程序与安装包，检查安装包内包含更新后的主程序和二维码资源。
- 在实际管理台窗口检查标题完整、顶部二维码可见、联系窗口两页切换正常、二维码可扫描、底部按钮无裁切。

## 范围外

- 不修改 Android 客户端本次已完成的联系作者界面。
- 不修改托盘菜单联系作者行为。
- 不改变微信号、二维码源图或应用桌面图标。
- 不改变 VPN、分流、自动重连和自启动逻辑。
