# 分流模式手动切换控件设计

## 目标

在不改变现有两种分流语义的前提下，为用户增加两个可见、状态一致的手动切换入口：

- 双击托盘图标打开的管理台。
- 右键托盘菜单。

切换成功后配置文件、管理台、托盘菜单与当前实际路由必须显示同一模式。

## 模式文案

- `国内直连优先`：默认使用本地网络，仅国外白名单走 VPN，对应 `domestic_direct`。
- `国外 VPN 优先`：默认使用 VPN，仅国内白名单直连，对应 `foreign_direct`。

界面不使用容易误解的“国外直连”简称。

## 交互设计

### 管理台

在“启用分流”附近增加模式下拉框。状态快照提供当前 `split_mode`，管理台刷新时同步选中项；用户选择另一模式时发送带模式值的 `set_split_mode` 命令。状态同步期间不重复发送命令。

### 托盘菜单

增加“分流模式”分组，并提供两个可点击选项。当前模式显示勾选标记。点击当前模式不执行刷新；点击另一模式时调用与管理台相同的模式切换动作。

## 生效流程

1. 校验目标值只能是 `domestic_direct` 或 `foreign_direct`。
2. 若目标值等于当前值，直接返回。
3. 更新内存配置并保存 `config.yaml`。
4. 将新模式同步给 TUN Session 和两个界面的状态模型。
5. VPN 已连接且分流已启用时立即刷新实际规则：
   - TUN 后端保留 OpenConnect 登录，只重启 sing-box 并重新生成规则。
   - Cisco 静态后端清理已应用的分流路由，再按新模式重新应用。
6. VPN 未连接或分流关闭时只保存状态，下次连接或启用分流时使用新模式。

为避免两个入口连续点击造成交叉刷新，同一时刻只执行一次模式切换。

## 错误处理

- 配置保存失败：恢复内存中的旧模式，不刷新路由，显示保存失败。
- 运行时规则刷新失败：保留已保存的目标模式，显示“切换未完全生效，请重新连接”，且不把运行状态伪装成成功。
- 所有错误写入现有日志和 Dashboard 最近错误字段。

## 测试与验收

- Dashboard 命令校验、分发及状态快照包含 `split_mode`。
- 管理台脚本包含模式下拉框、准确文案及 `set_split_mode` 命令。
- 托盘两个模式选项的勾选状态与回调正确，同模式点击不重复执行。
- TUN Session 可线程安全更新模式，下一次 Refresh 生成目标模式规则。
- 主程序切换动作可保存配置、同步两处状态并触发对应后端刷新。
- 运行相关 Go 测试、全量 `go test ./...` 和 Windows 可执行文件构建。

## 范围外

- 不改变两种模式的既有路由语义。
- 不新增第三种模式。
- 不修改 VPN 账号、站点选择或 Codex 线路逻辑。
- 不自动提交或推送 Git。
